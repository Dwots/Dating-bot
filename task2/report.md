## Вывод

### 1. какой брокер показал большую пропускную способность:
Redis значительно превосходит RabbitMQ при работе с крупными сообщениями. На 100 KB Redis обработал в ~2 раза больше сообщений в секунду без единой потери, тогда как RabbitMQ потерял более половины.

### 2. Какой брокер лучше переносит увеличение размера сообщения:
Redis демонстрирует линейное увеличение задержки (от 0.2 мс до 1.1 мс) и сохраняет нулевые потери. RabbitMQ резко деградирует после порога ~10 KB.

### 3. При какой нагрузке `single instance RabbitMQ` и `single instance Redis` начинают деградировать:
- Redis: в рамках проведённых тестов деградация не выявлена.
- RabbitMQ: деградация начинается при 100 KB / 5000 msg/s (потери 53.5%).

### 4. Какой инструмент лучше подходит для такого сценария и почему:

Для сценария высокоскоростной передачи сообщений переменного размера, в том числе крупных, Redis является предпочтительным выбором благодаря высокой производительности на больших сообщениях и отсутствию потерь даже при высоких нагрузках.

RabbitMQ остаётся хорошим выбором для надёжной маршрутизации при умеренных нагрузках.
Для передачи больших файлов через RabbitMQ потребуется дополнительная настройка (увеличение frame_max, использование отдельных хранилищ и т.д.).
